# SoloDesk UI design direction

Updated 17 October 2026. This is a design-stage contract for the complete product and an isolated reference, not authorization to implement business features.

- **Job and audience:** Freelance software engineers and small teams repeatedly plan delivery, capture time, invoice clients and review collections. Mode: Operate. A useful screen makes the next permitted action and the reliability of its data clear.
- **Confirmed direction:** The user selected the familiar productivity-app direction from the reference, then named **Linear, Notion and GitHub** as quality/feel references. Carry forward familiar navigation, quiet typography, precise tables and useful detail views; do not copy their branding or imply partnership. Preserve SoloDesk's supplied graphite/silver logo. Use blue for actions/selection, with separate semantic states.
- **Confirmed experience:** Both light/dark themes, System default; spacious layout with larger controls; English/Arabic full RTL. Clear row structure and generous group spacing take precedence over compact dashboards. Optional future density changes require approval; no compact default.
- **Composition:** Sidebar, slim global utilities, page title/action, scoped filters and spacious task/project table. Entity pages use tabs and optional context. Timer, workspace and honest save/sync status remain discoverable. Scope/work/time/billing links explain a project when useful, without becoming decorative branding or forced navigation.
- **Outcome:** A user can identify current workspace, priority work, timer state, local/cloud save state and permitted next action. Financial review exposes exact currency/source/version and online authority. No fictitious earnings or misleading paid/saved claims.
- **Deliverables:** Root DESIGN.md, reusable token specification, component/interaction rules, full screen inventory, all 151 feature-phase mappings, quality/decision gates and a standalone visual reference. Running app, dependencies, cloud configuration and original logos remain unchanged.
- **Ranges and states:** Long Arabic/English legal names; mixed-direction IDs; many-row tables; 0/2/3-decimal currencies; incomplete offline data; permission-hidden finance; uncertain timer recovery; unknown issuance outcome. Every feature inherits loading/empty/error/offline/recovery plus applicable dirty/read-only/immutable states.
- **Boundary:** Static reference is illustrative and disconnected from app data. Generated concept images are exploration aids, not final UI text or an implemented product. Domain specs own financial, authorization and synchronization behavior. Fonts, exact tokens and minimum window geometry are proposed implementation values subject to review and verification.
