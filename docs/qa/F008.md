## Quickstart Walkthrough Trace

All 6 scenarios defined in `specs/008-managed-backend-and-tenant-isolation/quickstart.md` were executed and verified against the synthetic emulator:

1. **Scenario 1: Strict Multi-Tenant Data Isolation & RLS Boundary**:
   - Alice (Workspace Alpha) queried `clients`, `projects`, `tasks`, `time_entries` and received only Alpha records. Beta records returned empty sets.
   - Alice attempted direct insert into Beta tenant $\rightarrow$ rejected with `42501 insufficient privilege`.
   - Aggregates on `clients` and `tasks` returned exact counts for caller workspace, with zero leakage of other tenants' counts.
2. **Scenario 2: Real-Time Role Lifecycle & Continuity Defense**:
   - Bob (Contributor in Alpha) permitted to create draft time entries; rejected when attempting member deletion or project deletion (`403 Forbidden`).
   - Bob's membership status updated to `suspended` $\rightarrow$ subsequent commands immediately rejected without cache lag.
   - Attempt to delete or demote Alice (sole owner of Alpha) $\rightarrow$ rejected by `trg_prevent_last_owner_delete`.
   - Two-phase ownership transfer initiated to nominated admin; completed only upon explicit nominee acceptance.
3. **Scenario 3: Private Object Storage & Expiring Signed Download URLs**:
   - Direct HTTP request to `/storage/v1/object/workspaces/ws_alpha_01/...` without signed token $\rightarrow$ 403 Forbidden.
   - Storage path with directory traversal (`../`) $\rightarrow$ rejected with 400 Bad Request.
   - Signed URL issued with 900-second (15-minute) lifetime; successful download at $T + 60\text{s}$, rejected with ExpiredToken at $T + 901\text{s}$.
   - Beta member attempted deletion of Alpha object $\rightarrow$ rejected with 403 Forbidden.
4. **Scenario 4: Relational Composite Foreign Key Defense**:
   - Attempt to insert project referencing client in another workspace $\rightarrow$ rejected with SQLSTATE 23503 foreign key violation.
   - Attempt to mutate `workspace_id` on existing project or client $\rightarrow$ rejected with abort trigger.
   - Multi-entity batch transaction containing mismatched workspace IDs $\rightarrow$ rejected and rolled back in entirety.
5. **Scenario 5: Quota Tracking & Non-Destructive Offline Degradation**:
   - Quota utilization tracked across DB, Object Storage, and Egress; alert tiers triggered at 70%, 85%, 95%, and 100%.
   - At 100% capacity, upload halted with 507 `STORAGE_UNAVAILABLE`; 100% of existing records remained intact and readable.
   - Disconnection from cloud backend $\rightarrow$ `DegradedModeManager` cleanly transitioned to `offline_degraded`, committed edits to local encrypted SQLite outbox (F007), and recovered to `operational` upon reconnection.
6. **Scenario 6: Secret Distribution & Client Bundle Isolation**:
   - Static scan across all packaged client directories confirmed zero leaks of `service_role` tokens or raw Postgres connection strings.
   - Preload and renderer contracts verify zero exposure of backend credentials.
