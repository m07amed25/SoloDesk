## PostgreSQL & Local Supabase Database Verification

- **Migration Script**: `supabase/migrations/20261023000013_f013_member_invitations.sql`
- **Private Schema Objects**:
  - `private.workspace_invitation_policies`: Opaque offer allowlists, tenant-isolated by `workspace_id`.
  - `private.workspace_invitations`: Canonical UUIDv4 invitation ID, revision, recipient binding key, offer reference, monotonic lifecycle state machine (`pending`, `accepted`, `revoked`, `expired`, `superseded`).
  - `private.invitation_generations`: Generation counter, domain-separated secret hash (`sha256(secret)`), selector (`sel_` + 32 hex chars), authoritative database expiry.
  - `private.invitation_delivery_attempts`: Delivery status (`queued`, `provider_accepted`, `delivered`, `bounced`, `suppressed`, `failed`, `rate_limited`, `unknown`), sink name, provider digest.
  - `private.invitation_redemption_attempts`: Short-lived continuation token hash, client IP digest, user agent digest, bound user ID.
  - `private.invitation_audit_events`: Immutable audit projections for invitation lifecycle events.
- **Public Integration**:
  - `public.workspace_memberships`: Inserted only upon atomic acceptance; contains accepted invitation provenance (`provenance_invitation_id`, `provenance_generation`).
  - `private.command_operations`: Reuses F009 authoritative operation claims and semantic digests for idempotent replay.
- **Restricted RPC Functions**:
  - Fixed `search_path = private, public, pg_temp`, `SECURITY DEFINER`, owned by least-privilege role.
  - Direct table grants to `anon` and `authenticated` are revoked.
  - Grants restricted to `service_role` and specific security-definer entry points deriving actor from `auth.uid()`.
- **Rollback Proof**:
  - Tested in `tests/f013/integration/invitation-rollback.test.mjs`.
  - Disabling RPC grants or setting policy `enabled = false` shuts down invitation entry points while keeping all historical invitations, audit records, and accepted memberships intact.
