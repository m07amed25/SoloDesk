## Delivered Cloud & Tenant Isolation Boundary

- **PostgreSQL Multi-Tenant Schema & RLS Policies**:
  - `workspace_tenants` represents isolated workspace tenants with strict immutability triggers (`trg_immutable_workspace_tenants_id`).
  - `workspace_memberships` establishes user-to-workspace roles (`owner`, `admin`, `contributor`, `viewer`) with forced Row Level Security (`has_active_membership`, `get_workspace_role`).
  - Immutability trigger `reject_workspace_id_mutation()` attached across all tenant domain tables (`workspace_memberships`, `clients`, `projects`, `tasks`, `time_entries`, `tenant_storage_objects`) preventing tenant reattribution.
  - Last-owner continuity defense trigger `trg_prevent_last_owner_delete` prevents orphaned workspaces by halting last active owner deletion or demotion.
- **Role Authorization & Continuity**:
  - `role-authorizer.ts` implements the capability matrix enforcing action authorization per role.
  - `ownership-transfer.ts` implements atomic two-phase ownership transfer (`prepareTransfer`, `acceptTransfer`).
  - `audit-service.ts` provides append-only tenant audit event logging (`tenant_audit_events`).
- **Private Object Storage & 15-Minute Signed URLs**:
  - Migration `20261020000005_private_storage_setup.sql` provisions private bucket `workspaces` (`public = false`) and storage RLS policies.
  - `storage-path.ts` enforces tenant-partitioned canonical storage paths (`workspaces/<workspace_id>/<category>/<entity_id>/<object_id>-<filename>`) with strict directory traversal (`..`) defense.
  - `storage-signed-url/index.ts` issues time-limited signed download tokens with a strict 900-second (15-minute) lifetime, verifiable only by active workspace members.
- **Composite Foreign Key Relational Defense**:
  - `20261020000007_domain_composite_tables.sql` establishes composite foreign keys `(workspace_id, parent_id)` on `projects`, `tasks`, and `time_entries` enforcing tenant graph boundaries at the database engine level (throwing SQLSTATE 23503 on cross-tenant pointers independently of RLS).
  - `batch-transaction.ts` enforces uniform tenant attribution across atomic multi-entity batch transactions.
- **Provider Quota Resilience & Degraded Offline Fallback**:
  - `20261020000006_provider_quota_profiles.sql` and `quota.ts` track storage, object, and egress limits with progressive tier progression (`normal`, `warning_70`, `warning_85`, `critical_95`, `exhausted_100`).
  - Pre-flight write check asserts quota capacity and halts writes cleanly with F003 `507 STORAGE_UNAVAILABLE` at 100% capacity while preserving 100% of existing records.
  - `degraded-mode-manager.ts` and `cloud-gateway-client.ts` transition desktop operations to the local encrypted SQLite outbox (F007) without data loss upon cloud disruption (503/507).
  - `QuotaWarningBanner.tsx` delivers bilingual English and Arabic alerts with WCAG 2.2 AA visible focus indicators and proper RTL/LTR layout direction.
- **Secret Isolation**:
  - `tooling/f008/test-secrets.mjs` verifies zero high-privilege `service_role` keys, database passwords, or superuser credentials in desktop client distributions or renderer code (FR-012, SC-009).

## Verification and Runbook

Run `npm run test:f008` (or `node tooling/f008/verify.mjs`), `npm run lint`, and `npm run typecheck`. All 6 verification suites run in process using the high-fidelity emulator (`better-sqlite3-multiple-ciphers`) with enforced foreign keys and custom RLS simulation.

In operational scenarios:

1. When storage hits 100% capacity, cloud edge functions reject new uploads with 507 `STORAGE_UNAVAILABLE`. The desktop client falls back to queuing edits in the local encrypted outbox until capacity is restored.
2. During cloud downtime, `DegradedModeManager` transitions client state to `offline_degraded`, displays the localized degraded banner, and retains local edits securely.
3. Ownership transfer requires acceptance by the designated admin nominee before relinquishing previous owner privileges.
