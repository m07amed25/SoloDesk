# F006 — Cross-platform key protection proof

Status: **candidate implementation in progress**. F006 uses synthetic local data only. [Specification](../../specs/006-cross-platform-key-protection/spec.md), [design](../../specs/006-cross-platform-key-protection/plan.md), [tasks](../../specs/006-cross-platform-key-protection/tasks.md), and [observed QA](../qa/F006.md) have separate roles. A candidate build does not approve Q-07, Q-11, F007 adoption, merge or release.

## Candidate acceptance criteria (Q-07)

Engineering will evaluate an encrypted SQLite-compatible native adapter against Electron 44.8.0, Windows/macOS/Linux packaged builds, index/WAL/journal/temp behavior, exact reopen and wrong-key rejection. Every application-controlled raw file must be inventoried and contain no readable synthetic marker. The installed plain `better-sqlite3` is excluded from protected persistence.

The data key must be generated independently per local identity/data set and wrapped by a reviewed OS or user-unlock protection path. A locked, missing, denied or unprotected provider must fail closed. Linux `basic_text` is specifically rejected. The renderer gets no key, SQL, arbitrary path or generic crypto method. Staged attachments need a reviewed authenticated format outside the database adapter. Key change must preserve a complete decryptable prior or new generation across process interruption. Password reset cannot recover locally unsynced data without a surviving key or separately protected backup.

Security review must approve the adapter, crypto/file format, key wrapping, Linux alternative, recovery policy, dependency/license notices and threat limits **after** proof. No review or approval is claimed in this document.

## Boundaries

- F004 owns process, profile and checked preload boundaries. F006 may add only named safe status/actions there.
- F007 owns production encrypted cache, transaction/outbox and migration semantics. F006 never writes customer records.
- F010/F015/F016 own sign-in, device enrollment and offline authority. A local profile label alone is not a workspace grant.
- F023 owns actual attachment lifecycle; F025/F026 own backup and restore.
- Raw-file and key-loss limits must be explained in English and Arabic. Same-OS-user process compromise and already copied data are outside the key-wrapper guarantee; no secure-erasure claim is made.

## F007 consumption gate

### Interface and format specification

- **Format version**: `PROTECTION_FORMAT_VERSION = 1` (verified in `app/main/protection/types.ts`). Unknown format versions enter `recovery_required` without creating an empty replacement.
- **Closed safe reason codes**: `vault_locked`, `key_missing`, `protection_denied`, `unprotected_backend`, `integrity_failed`, `interrupted_rotation`, `unsupported_format` (defined in `app/shared/protection-contracts.ts`). Error responses exclude paths, keys, fixture text, and raw native exceptions.
- **Protection owners**: `ProtectionOwner` manages encrypted SQLite databases (`better-sqlite3-multiple-ciphers` in SQLCipher v4 mode with PBKDF2/HMAC-SHA512/AES-256-CBC) and authenticated staged files (`.stage` with AES-256-GCM and SHA-256 digest validation).
- **Key lifecycle**: `rotateKey` enforces monotonic progression (`prepared` -> `candidate_written` -> `candidate_verified` -> `selected` -> `retired`) and `reconcileRotation` preserves prior decryptable state on interrupted key change.
- **Renderer bridge**: Zero raw keys, SQL commands, or file paths exposed across preload. Safe status inquiries via `solodesk.protection.getState()`.

### Consumption decision: BLOCKED

F007 consumption of the protection boundary remains **BLOCKED**. In accordance with the [native proof contract](../../specs/006-cross-platform-key-protection/contracts/native-proof.md#f007-consumption-gate), F007 may not persist customer data or business features until all declared native matrix targets provide passing native evidence.

### Remaining blockers

1. **Inaccessible Native Targets**: Windows x64 (DPAPI/Credential Manager) and macOS arm64 (Keychain) hosts are not accessible in this execution environment; their matrix rows remain `blocked`.
2. **Linux Native Keyring Session**: The test environment runs headless Linux where `safeStorage` reports `basic_text`. The system successfully demonstrated fail-closed denial (`unprotected_backend`) with zero on-disk leakage, but positive native OS vault proof requires an active `org.freedesktop.secrets` daemon.
3. **Formal Q-07 / Q-11 Approval**: Engineering and security owner sign-off on the candidate adapter and supported distribution matrix.
4. **F007 Implementation Authorization**: User authorization remains bounded to F006 governance proof with synthetic fixtures only. Production business persistence is deferred.
