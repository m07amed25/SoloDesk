# F002 — Automated CI and Verification Harness

Status: implementation in progress. [Specification](../../specs/002-ci-verification-harness/spec.md), [technical plan](../../specs/002-ci-verification-harness/plan.md), [tasks](../../specs/002-ci-verification-harness/tasks.md), [QA](../qa/F002.md).

The verification CLI distinguishes scoped baseline success, complete automated readiness, actual agent QA and final owner approval. Only observed execution counts as evidence.

F001 actual merge is verified. Customer workflows, encryption, cloud, financial rules, Arabic UI and release signing remain outside F002.

## Baseline commands

Use `npm ci --ignore-scripts --no-audit --no-fund` for locked setup. `npm run verify -- --profile baseline --base <actual-full-base-sha>` runs type/lint/build, launcher, F001 governance, documentation and verification contracts. Its scoped exit 0 is not full readiness; security/native/agent/owner stages remain separately required.

`npm run test:unit` and `npm run test:integration` invoke fixed leaf runners. Required zero/partial/skipped/TODO suites fail; recorded command strings never execute. Logs and JSON are bounded and redacted.

Ordinary isolated Node execution is the authoritative runner. In this restrictive tool sandbox, nested TAP output is unavailable; tests were separately executed outside that sandbox and report actual assertion counts. This is a tooling limitation, not a waiver.
