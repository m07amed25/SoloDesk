## Implemented source and proposal behavior

The eight-principle constitution is concrete v1.0.0; stale placeholder observations were corrected.
[Delivery governance](../development/delivery-governance.md) links the governing product/decision
sources. The local checker distinguishes required local references, fragments, external catalogue
links and fenced future examples. It rejects missing/escaping links and unsupported inline syntax.
The [PR template](../../.github/pull_request_template.md) covers the ten required description
sections; proposal checks enforce one correctly named F001 branch/primary PR targeting main.
Synthetic proposals do not invent real PR identities. Oversized splits require agreed new IDs
before implementation; fixes stay in the same open PR and later defects use linked maintenance.

## Evidence and owner review

The dependency-free Node checker validates version-1 phase/proposal/evidence/approval/history
records, all 26 local requirements and 22 scenarios, ten applicability subjects, artifacts,
canonical snapshot digests, changed-file coverage and explicit carry-forward assessments.
It rejects stale/failed/missing applicable results, blocking findings, unsupported outcome claims
and self-asserted consent. Text and JSON diagnostics use exit codes 0/1/2; external references stay
unfetched. Inputs are bounded (2 MiB/file, 32 MiB total, 512 files, 2,048 records/collection).

The [QA report](../qa/F001.md) and [evidence pack](../qa/F001.evidence.json) distinguish actual
command/policy observations from synthetic approval/merge examples. Green checks do not authorize
merge. Final user approval must identify the actual PR/head/base/evidence at a trusted human
source, independently of any mandatory platform review. Pending decisions remain pending.

## Lifecycle, repair and handoff

The policy distinguishes building, publication, automated checks, agent QA, owner review,
approval, actual merge and separately authorized release. Failed/blocked overlays keep the last
valid state and an owner/action. Material changes invalidate affected evidence and consent;
retain history and repair the same PR. Post-merge defects use linked maintenance/backout.
F002 consumes the CLI/record contract after F001 actually merges; generalized CI, provider/source
authentication, scanning and remote protection are its separately authorized scope.

Run the commands in [delivery governance](../development/delivery-governance.md#local-commands-and-content-sealing).
No application behavior, encryption, financial, Arabic UI, installer or native OS acceptance is
established by this tooling. No packages, cloud services, CI workflows or remote settings are added.
