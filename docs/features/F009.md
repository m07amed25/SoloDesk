# F009 — Authoritative command receipts and audit

Status: **partial synthetic implementation; production delivery incomplete** (20 October 2026).
[Specification](../../specs/009-authoritative-command-receipts/spec.md), [plan](../../specs/009-authoritative-command-receipts/plan.md), [tasks](../../specs/009-authoritative-command-receipts/tasks.md), and [QA](../qa/F009.md).

The TypeScript command helper and in-memory SQLite emulator exercise canonical SHA-256 intent, scoped replay, revision conflicts, atomic evidence rollback, receipt archival, reconciliation fences, audit projections, and event ordering. Contracts and English/Arabic receipt strings exist. These tests do not establish PostgreSQL concurrency, deployed credential verification, or accessible rendered UI.

The gateway requires an injected credential verifier, registry, membership reader, and database adapter for F009. Missing configuration fails closed; legacy F008 test-token authentication is not used for F009. Device identity must come from the verifier. The synchronous transaction interface rejects asynchronous membership readers at execution time. A production adapter must enforce current action/resource authority within the owning database transaction.

The migration defines evidence tables, indexes, RLS and privilege restrictions, plus mutation rejection triggers. It does **not** define `private.execute_authoritative_command`, `private.reconcile_operation`, or audit query functions. No PostgreSQL adapter, audit query/export service, recovery integrity verifier, or rendered receipt/audit UI is delivered. Reconciliation in the emulator stores a synthetic fence marker rather than the original intent digest. These remain open tasks; synthetic results cannot satisfy their production acceptance criteria.

Service operator access remains disabled. Production retention and service audit policy remain unapproved gates. No cloud resources were provisioned.
